# 矿脉重生 (VeinRebirth)

> 旧名「矿物生成配置 (OreGenConfig)」，1.2.0 起更名为「矿脉重生」。

参照《我的世界》1.12.2「自定义世界 → 矿物设置」的思路做的矿物生成配置模组。
每种矿物的**生成数量 / 生成规模 / 生成权重 / 生成高度上下限**都能在游戏内用滑块实时修改，
也能直接编辑带中文注释的配置文件；改完还能用命令让已生成的区块刷出新的矿物。
1.1.0 起还能**自动识别其它模组添加的矿石**，需要时可以让本模组「接管」它们的生成。
1.2.1 起，模组矿物会先判定「该长在浅层的石头里还是深层的深板岩里」——没有深板岩变体的矿石
**只生成在浅层**，不会再在深层长成浅层矿石的样子。
1.3.0 起**界面与命令支持中英双语**，跟随客户端语言自动切换；模组矿物的名字（含深板岩变体）
直接取方块自身的翻译，因此换语言时它们也跟着换。

## 主要能力

- **原版 11 种矿物整体接管**——煤炭、铜、铁、金、红石、钻石、青金石、绿宝石、下界石英、下界金、远古残骸
- **自动识别其它模组的矿石**——扫方块注册表 + `forge:ores` 标签，默认不接管，可逐种开启
- **游戏内滑块界面**——左侧为可垂直滚动的矿物列表（带搜索框），按「原版矿物 / 各模组」分节
- **内置 5 套预设 + 分享码**——整套数值压成 112 字符左右的文本，可直接在聊天栏里整段发给别人
  （命令输出的那行码点一下就复制，**需先按 `T` 把聊天栏打开**；界面里另有一键「复制此码」）
- **区块矿物刷新**——`/veinrebirth refresh [半径] [clean | clean all]`，让旧区块按新配置重新生成或清除残留
- **中英双语界面**——界面与命令输出走语言文件（`assets/veinrebirth/lang/`），跟随客户端语言；
  模组矿物的名字取方块自身翻译，原版与其它模组提供什么就显示什么
- **大型矿脉可控**——1.18+ 的铜矿脉 / 铁矿脉可单独调节

## 命令

主命令是 `/veinrebirth`；**旧名 `/orecfg` 与 `/oregenconfig` 仍然可用**（1.1.x 的兼容别名）。

## 安装

1. 安装 Minecraft 1.20.1 + Forge 47.x
2. 把 `矿脉重生 VeinRebirth-<版本>.jar` 放进 `.minecraft/mods/`（服务端放服务端 `mods/`）
3. 首次进入世界时会自动生成 `config/veinrebirth-ores.toml`（含中文注释）
4. 进游戏后执行 `/veinrebirth info diamond`，能看到数值输出即为安装成功

## 构建

需要 JDK 17：

```bash
./gradlew build          # 产物：build/libs/veinrebirth-1.3.0.jar
```

改版本号只需动 `gradle.properties` 里的 `mod_version`。

## 开发工具

`tools/` 下是开发期的验证脚本，**不参与构建，也不会打进 jar**——jar 里只有 `src/main/` 的
Java 代码与数据包。它们负责核对那些在游戏里用肉眼看不出来的事：存档里到底生成了多少矿石、
清理功能有没有漏掉区块、界面在低分辨率下会不会越界。

| 文件 | 用途 |
| --- | --- |
| `audit_ore_variants.py` | 扫描整合包内所有模组，列出「浅层矿石缺少深板岩变体」的条目——这类矿物被接管后会在深层长出浅层矿石 |
| `gui_layout_check.py` | 把界面布局算法复刻成纯算术，穷举分辨率检查控件越界 / 重叠 / 文字溢出，不依赖游戏 |
| `verify_jar.py` | 校验构建产物：占位符是否展开、是否完成 SRG 重映射、数据包是否完整 |
| `OreProbe/` | 测试用假模组，注册锡 / 银 / 铅等假矿石与 `forge` 标签，用来验证「自动识别第三方模组矿物」这条链路。**不要放进正式整合包** |

```bash
python tools/audit_ore_variants.py <你的 mods 目录> -o 报告.md
python tools/verify_jar.py          # 不带参数时自动取 build/libs 下最新的产物
python tools/gui_layout_check.py
```
